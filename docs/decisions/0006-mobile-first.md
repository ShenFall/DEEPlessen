# ADR-0006 手机优先：课堂是现场，桌面是后台

- 状态：已采纳
- 日期：2026-11-21
- 取代：v0.2–v0.4 中「桌面终端为主」的布局前提（02-brand 左栏、06-screens S3、10-tasks M0）

## 背景

前三版都按桌面设计：56px 左侧栏、8×5 矩阵、`⌘K` 命令行、拖文件。

真实场景是：

> 我大概率是在课堂课件收作业，所以手机用的会多。

拆开看，这句话改变了四件事：

1. **姿势**：站着、一只手拿作业、另一只手点手机 → 必须拇指可达
2. **节奏**：学生一个个递过来，几秒一个 → 不能有确认弹窗
3. **环境**：教室灯光强、屏幕反光 → 纯黑反而像镜子
4. **网络**：教学楼信号常年 1 格 → 不能等网络

键盘命令行在这里彻底失效：软键盘吃掉半个屏幕，中文输入法还要选字。

## 决策

1. **手机（375px 起）是主设计目标**，桌面是增强，不是主体。
2. **两套操作隐喻，而非同一套缩水**：
   - 手机 = **现场点名**：4 列网格、拇指区、点完自动滚到下一个、撤销 toast
   - 桌面 = **事后对账**：矩阵、键盘、命令行、批量补录
3. **离线优先**：PWA + IndexedDB，标记操作永不等待网络，顶部常驻 `● 离线 · 已存本地`。
4. **Excel 成为主导入格式**（xlsx/xls），CSV 降为兼容项。
5. **手机端深浅跟随系统**；深空主题在手机上整体提一档亮度（`#0F1620` 而非 `#070A12`），对抗强光。
6. 断点：`<720px` 手机 / `720–1100` 平板两栏 / `>1100` 桌面。

## 后果

好处：
- 主场景真的快：单手、离线、48px 目标、无弹窗
- 桌面端可以做重活（批量粘贴、统计、发资料），两种场景各得其所

代价：
- 两套交互要维护，组件不能完全复用
- 命令行从"核心交互"降级为"桌面可选"，M2 的验收方式要改
- 矩阵规格分两套（8 列 vs 4 列），6 个界面要出两份规格

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 只做响应式（桌面缩小到手机） | 8 列挤成 5 列，每格 < 40px，教室里必点错 |
| 手机只做"查看 DDL"（v0.1 的判断） | 主场景就在手机，等于不做 |
| 用扫码签到替代点名 | 依赖学生配合 + 网络，老师站在讲台上等的时候不能赌 |
| 手机也保留命令行 | 软键盘 + 中文选字，比点两下慢得多 |
