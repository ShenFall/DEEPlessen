# ADR-0002 名字永不消失，位置恒定

- 状态：已采纳
- 日期：2026-11-21

## 背景

初版对账交互是「点一下名字，格子消失，剩下的人往前补位」。这是大多数清单类产品的默认做法，但在 40 人名单上会出三个问题：

1. **手指失去坐标**。勾掉一个人，后面所有人左移一格，下一个目标就跑到别处去了。连续勾 39 次，每次都要重新找。
2. **误操作不可逆**。人一旦消失，你没法「再点一下取消」，只能去「已交」列表里把他捞回来。
3. **失去全局感**。看不到「这一排都交了」的空间形态，而这个形态恰恰是学委判断进度最依赖的东西。

## 决策

1. 状态变化**不改变任何坐标**。网格永远按学号排序，永不重排。
2. 点一下只是**降权**：`●` → `○`，颜色降到 `--mute`，透明度 45%，下移 4px。格子还在原地。
3. 再点一下**复原**，且不消耗任何确认步骤。
4. 撤销栈保留最近 20 步，`Z` 触发，带 toast。
5. 「还剩几个人」由一个**独立的队列栏**承担——那里可以消失，因为它本来就是待办清单，消失是它的语义。

## 后果

好处：
- 肌肉记忆成立，连续标记的速度随熟练度提升
- 误触成本为 0
- 「已交」和「未交」在同一个空间里形成图形，扫一眼就知道分布

代价：
- 名单占满屏宽，无法做「未交优先」的排序优化
- 已交的人仍然占位置，40 人不能折叠（除非手动折叠已交行）

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 勾选后消失并补位 | 见上，坐标漂移是致命的 |
| 分两个列表（未交/已交） | 每次操作都要在两个列表间跳跃，反而更慢 |
| 未交优先排序 | 每次状态变化都重排，等于把坐标漂移做成了默认行为 |
