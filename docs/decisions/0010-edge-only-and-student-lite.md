# ADR-0010 学委端只支持 Edge；学生端独立构建、兼容优先

- 状态：已采纳
- 日期：2026-11-22
- 相关：ADR-0008（本地库 + 对象存储）

## 背景

两端的使用者完全不同：

- **学委端**：只有你一个人用，固定 Windows + Edge，可以接受"只在 Edge 里能跑"
- **学生端**：全班 30 人，微信内置浏览器、Safari、安卓各色浏览器，**任何一个打不开就等于失败**

用一套代码同时满足两端，会让学委端被最低兼容性拖住，而学生端被框架体积拖累。

## 决策

### 一、学委端：Edge Only

- 直接用 File System Access API 读写本地库（`showDirectoryPicker`），不做降级
- 可以用最新语法，不引 polyfill
- 不追求"换台电脑也能用"——库跟着目录走，应用本身就是网页

代价：**只在 Edge/Chromium 桌面版可用**。Safari、Firefox、手机浏览器打开会提示"请在电脑 Edge 中打开"。

### 二、学生端：独立构建，兼容优先

- 独立目录 `student/`，**不引 React**，纯 HTML + CSS + 少量原生 JS
- 语法保守（不用可选链、不用顶层 await），打包目标 ES2017
- 首屏目标 **< 30KB**，弱网 3 秒内可交互
- 不用 Service Worker、不用 WebP 以外的新图片格式
- 下载用 `<a href download>` + `Content-Disposition: attachment`

### 三、共享的只有数据

两端共享的不是代码，是**对象存储里的清单 JSON**：

```
学委端 ──写──> R2: manifest.json + 文件
学生端 ──读──> R2: manifest.json + 文件
```

各自渲染，互不依赖。

## 后果

好处：
- 学委端可以放心用新 API，开发快
- 学生端体积小、兼容广，弱网也能开
- 一端出问题不影响另一端

代价：
- 两套 UI 代码（但学生端只有一屏，成本低）
- 两套构建与部署配置
- 清单 JSON 的字段变更要两边同步

## 否决方案

| 方案 | 否决理由 |
|---|---|
| 一套 React 同时服务两端 | 学生端要背 300KB，微信弱网下白屏 |
| 学委端也做兼容降级 | 唯一用户就是你自己，降级只会拖慢开发 |
| 学生端用 SSR/动态服务 | 又要一台服务器，违背 ADR-0008 |
