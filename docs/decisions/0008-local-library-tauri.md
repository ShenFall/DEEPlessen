# ADR-0008 本地库 + 桌面壳；分发只走对象存储

- 状态：已采纳
- 日期：2026-11-22
- 相关：ADR-0001（学生端公开只读）、ADR-0006（手机优先）

## 背景

三条诉求同时成立：

1. 手机只做"没有电脑时才能做的事"：点名、发链接
2. 文件录入与仓库管理在电脑上
3. **资料要存在自己的电脑上**，不想额外租服务器；且担心外部攻击与个人文件泄露

第 3 条里藏着一个真实的危险：微信下载目录里**不只有课程资料**，还有私人文件。任何"自动扫描 / 自动同步"的设计都等于把私人文件纳入上传候选。

## 决策

### 一、三端分工

| 端 | 形态 | 职责 |
|---|---|---|
| 手机 | PWA | 对账点名、发取件链接、看 DDL |
| 电脑 | **Tauri 桌面壳** | 库管理、Excel 导入、发布、统计 |
| 学生 | 静态页（公网） | 只读浏览与下载 |

电脑端用桌面壳而不是纯 Web，理由只有两个，但都不可替代：
- **能读写本地库目录**（Web 只有 Chrome/Edge 的 File System Access API，Safari 完全没有）
- **能监听微信下载目录做"待整理"提示**（手机端受沙盒限制，永远做不到）

### 二、本地是真相，云端只是副本

- 文件原件永远在本地库目录（`<库根>/materials/<课程>/`），**只此一份，永不自动删除**
- **"发布"是显式动作**：勾选 → 复制一份到对象存储 → 生成签名链接
- 界面必须同时显示两种状态：`本地 ✓ / 云端 ✓`、`本地 ✓ / 云端 —`
- "下架"只删云端副本，本地纹丝不动

### 三、安全边界：三层隔离

**目录隔离**
- 应用只认识一个库根目录（初始化时由你亲手选定），其余一切不可见
- 微信下载目录**不是库**，只是"可拖入的来源"。应用不索引、不扫描、不缓存它
- 库根不得设在用户主目录或桌面，避免误伤与误授权

**动作隔离**
- 没有任何"自动同步 / 后台上传"。文件离开本机只有一条路径：你点了「发布」
- 发布的最小单位是"一个文件"，不是"一个文件夹"
- 微信目录里的文件被拖入后是**复制**进库，原文件不动

**网络隔离**
- 桌面端**不监听任何公网端口**，不内建 HTTP 服务
- 分发只走对象存储的签名 URL（7 天过期，随机 slug，不可枚举）
- 应用不申请管理员权限

### 四、为什么不自己搭一台"资料服务器"

| | 自建公网文件服务 | 对象存储分发 |
|---|---|---|
| 攻击面 | 整台机器：OS、SSH/RDP、Web 中间件、依赖链 | 一个桶 + 一个签名 URL |
| 必须常开 | 是（断电/休眠即失效） | 否 |
| 个人文件风险 | 目录穿越、配置失误即全家桶暴露 | 桶内只有已发布的副本 |
| 成本 | 0 + 一台常开的机器 | 免费额度内 ≈ 0 |

**把自己的电脑暴露到公网，比上传几个已发布的文件风险高一个数量级。** 你要防的不是"Cloudflare 被黑"，而是"自己配错一个静态目录，把 `D:\` 挂上去了"。

## 后果

好处：
- 原件、标签、历史都在本地，断网/欠费/服务挂掉不影响整理工作
- 私人文件从结构上就不在"可发布"集合里，不依赖你的自律
- 手机端仍然轻（PWA，不装 App）

代价：
- 电脑端要维护两个形态（Web 预览 + Tauri 壳），构建链更复杂
- 学生下载依赖对象存储可用（但这是最便宜的一环）
- 桌面壳需要签名/分发，Windows 首次运行会有 SmartScreen 提示

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 纯 Web + File System Access API | Safari 不支持；每次重开要重新授权；无法监听目录 |
| 自建公网文件服务器 + 内网穿透 | 攻击面是整个 OS；电脑必须常开；课堂发链接时断电即失效 |
| 全部走云（无本地库） | 与"资料在我手里"直接冲突 |
| 手机端也做文件上传 | 手机沙盒读不到微信目录；课堂上一只手传大文件不现实 |
