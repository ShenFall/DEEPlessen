# ADR-0004 流式标记优先，批量对账降级为补录

- 状态：已采纳
- 日期：2026-11-21
- 取代：v0.2 中「主操作是粘贴已交名单做差集」的判断（05-flows B）

## 背景

v0.2 把对账的主路径设计成「一次性粘贴已交名单 → 自动差集」。实际节奏不是这样：

> 更多是零星几个人陆陆续续交作业。我收到第 27 份时，想知道还剩谁。

这是两个不同的问题被混淆了：

- **批量模型**假设：某一时刻你手上有一份完整的「谁交了」名单，系统负责做集合差。
- **流式模型**才是现实：从第一个人到最后一个人之间隔了 4 个小时，学委每收到一个就记一个，中途随时可能想知道「现在还剩谁」。

批量模型还有一个隐蔽的失败点：**它要求你先攒够一份名单才能开始用**。而真实情况下第一个人 19:02 就交了，那时你根本没有名单。

## 决策

1. **主模型改为 REPL**：默认全员未交，每次「输入一个人 → 回车 → 标记」，循环 40 次。
2. **入口收敛为一条命令行**（`deep:~/ds-hw4$`）。拖入文件、粘贴文本、敲名字，都走这条线，输出统一为「标记 + 一条证据」。
3. **答案不靠查询，靠对比**：「27 暗 + 13 亮」本身就是答案，所以已交的格子必须留在原位（见 ADR-0002）。
4. **批量导入降级为补录**，入口收进「⋯」，只在两种场景使用：白天收纸质、事后追认历史。
5. **左侧 QUEUE 栏保留**。批量场景下它确实和矩阵冗余，但流式场景下它是唯一的「剩余数量」视图，且随标记实时缩短，提供进度反馈。
6. **`suspect` 从格子层移到输入层**：流式时每条记录都有人为动作，匹配不上就当场问「这是谁」，不给格子留黄边。三态只在批量补录路径中短暂存在。

## 后果

好处：
- 第 1 个人交的时候就能开始用，不需要等待「名单齐全」
- 每次标记 2–3 秒，40 人约 100 秒，且可间断（随时回来继续）
- 「还剩谁」是零成本查询，视线一扫即可，不需要打开任何面板
- 自动积累 `submittedAt`，期末算超时不用回忆

代价：
- 需要 40 次输入动作（但每次 3 键，比 40 次鼠标找位置快）
- 矩阵占满屏宽，13 个亮格是散落的，不会自动聚拢成列表
- 必须处理「重复提交」「转专业」「敲错人」三种噪声

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 只做批量导入（v0.2） | 第一个交的人出现时无法使用；零星交付时每次都要重导全量名单 |
| 勾选后消失、剩余人聚拢 | 剩下的 13 格会混入「还没交」和「还没点到」两种语义，无法区分（详见 ADR-0002） |
| 每次标记后重排「未交优先」 | 坐标漂移，40 次标记 = 40 次重新找位置 |
| 每交一个弹窗确认 | 40 次弹窗，会让人放弃使用 |
