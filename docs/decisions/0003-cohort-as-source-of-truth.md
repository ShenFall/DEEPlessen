# ADR-0003 花名册是一等公民

- 状态：已采纳
- 日期：2026-11-21

## 背景

需求原话：「我有班级花名册，我希望可以自行导入，我换班级后可以继续用。」

这句话里其实有两个独立需求，容易被合并成一个「导入功能」草草了事：

1. 花名册要能进来，而且格式很脏（教务系统导出、Excel 手改、微信群里的名单）
2. 换班/换学期之后，**整个系统还能继续用**，而不是重开一个

## 决策

1. 引入 `Cohort`（班级）作为顶层容器，与 `Course`（课程）多对多。学生只属于班级，不直接属于课程。
2. 所有业务数据（作业、提交、资料）都同时带 `cohortId` 和 `semester`，从第一天就分好，**不做数据迁移**。
3. 学生主键内部生成、永不变；学号只是可空的业务字段。这样学号改了一次也不会把历史记录打断。
4. 引入 `Alias` 表：微信昵称、错别字、文件名写法都记下来。匹配成功一次就记住，这是系统会「越用越准」的唯一机制。
5. 重复导入走「合并」：按学号对齐，新增的加入，消失的标 `inactive` 而不是删除。
6. 旧班级归档（`archived`）而非删除，随时可切回去看历史。

## 后果

好处：
- 换班 = 新建班级 + 导入一次，3 分钟，历史全在
- 一门课带两个班，只需把课程挂到两个 cohort 上
- 转专业、休学的学生不会破坏历史数据

代价：
- 数据模型比「一个班一张表」复杂，所有查询都要带 cohort 条件
- 首次使用时必须走完导入向导，不能「先用起来再说」

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 单一班级，换班时清空重来 | 历史欠交记录全丢，而这是期末跟老师交代的唯一凭据 |
| 学生直接挂课程 | 一门课两个班时会重复建人，同一个人出现两次 |
| 用学号做主键 | 学号会变（转专业、留级），一变历史就断 |
