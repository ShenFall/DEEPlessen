# ADR-0009 不做顺序引导，做常驻撤销

- 状态：已采纳
- 日期：2026-11-22
- 取代：M0-0.8「自动前进 / 自动指下一个」

## 背景

0.8 实现的是：标记一个人之后，把"下一个未交的人"高亮出来（金线 + 圆点），必要时滚动到它。

真机试用一轮，结论是**没用**。

## 分析

这个功能有一个隐藏前提：**操作是按名单顺序线性推进的**。

- 老师念名字，学委一个个对照 → 顺序引导成立，"下一个"就是下一行
- 但实际是：学生随机走上来递作业，学委**找谁点谁** → 随机访问

在随机访问下，"下一个未交的人"和"下一个交作业的人"是两件无关的事。指出来的人往往不在你面前，反而多一处视觉噪音。

顺带也否掉了"加搜索框快速定位"的冲动：28 人 4×7 全在屏幕上，扫视约 2 秒就能找到；调出键盘再输入，更慢。

## 决策

1. **删除顺序引导**：去掉高亮、圆点、自动滚动、以及那个开关。
2. **底栏改为常驻「撤销 · 姓名」**，无时限。它解决的是真实高频问题（手指在抖、屏幕在晃、点到隔壁），且不需要任何前提。
3. toast 里的 3.5 秒撤销**保留**：它承担"确认刚才点了谁 + 允许立即反悔"，和底栏的常驻撤销是两个不同场景。
4. 以后不再做顺序引导类功能（推荐下一个、批量推进），除非出现真正的"按名单点名"场景。

## 后果

好处：
- 少一个开关、少一种视觉噪音，界面更安静
- 误标可以随时回退，且不限时间

代价：
- 失去"连点不抬头"的流畅感——但在随机访问场景里这种流畅本来就不存在
- 历史栈只支持"撤销"，不支持"重做"（v1 不需要）

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 保留但默认关闭 | 一个没人开的开关等于没有，还占位置 |
| 改成"按学号顺序逐行确认模式" | 那是"老师点名"的流程，不是"收作业"的流程 |
| 加搜索框替代 | 28 人扫视更快；人多时再议（那时是另一个问题） |
