# ADR-0001 单人后台 + 公开取件页

- 状态：已采纳
- 日期：2026-11-21
- 取代：v0.1 中「不做学生端」的判断

## 背景

v0.1 的结论是「不做学生端」，理由是学生不会注册账号。但真实的痛点是「资料太多太杂，总有人来问我要」——如果学生不能自助，学委就永远是人工客服。这两件事不矛盾：**学生需要的是"能拿到东西"，不是"拥有账号"。**

## 决策

系统有两个前台，但**只有一个用户体系**：

- 学委端：单口令，全功能读写
- 学生端：公开只读页面，无账号、无登录、无身份

学生端的能力边界是「看 + 下」，一个字节的写权限都没有。

## 后果

好处：
- 学生侧零学习成本，扫码即用
- 没有权限模型、没有找回密码、没有用户管理
- 后端几乎无状态，成本接近 0

代价：
- 无法做「仅本班可见」的精细控制，只能靠「不公开的链接 + 口令」
- 无法知道是谁下载的（这是有意的：不做个人追踪）
- 资料一旦泄露到班外，技术上无法追责，只能靠学期末自动下线降低影响

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 学生也要注册 | 一半人会在注册页流失，学委反而收到更多「怎么登不上去」 |
| 学号白名单 | 学委无法验证学号真伪，白名单只是心理安慰 |
| 微信群机器人自动发文件 | 微信无开放接口，任何实现都是外挂，随时会挂 |
