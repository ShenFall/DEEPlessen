# ADR-0005 动效分三层，功能层不许华丽

- 状态：已采纳
- 日期：2026-11-21

## 背景

需求：「动效也希望是比较华丽」。

但同一个产品的使用场景是：23:57，宿舍熄灯，学委在数 40 个人谁没交，一个 DDL 还有 3 分钟。
这两件事指向相反的设计方向。直接听需求做「全站华丽」，会把这个工具变成一个好看的、但每次用都想砸键盘的东西。

## 决策

动效分三层，按「是否影响判断」切分，而不是按「好看程度」切分：

| 层 | 定义 | 时长 | 默认 |
|---|---|---|---|
| L1 功能 | 因果反馈：点了有没有生效、面板从哪来 | ≤250ms | 开，不可关 |
| L2 状态 | 状态跃迁的仪式感：收齐、换挡、撤销 | 240–400ms | 开，可关 |
| L3 装饰 | 与任务无关的氛围：粒子、视差、逐字 | 400ms–30s | **关**，可开 |

配套三条：

1. L3 只允许出现在「没有任务在等」的界面上（空状态、收齐后、首页顶部）。对账台属于「有任务在等」，永久禁入。
2. `prefers-reduced-motion` 强制 L2/L3 关闭。
3. 提供「静默 / 标准 / 华丽」三档预设，默认标准。「华丽」是一份具体的 6 项清单，不是「到处加动画」。

## 后果

好处：
- 想要的效果全都有，但只在你放松的时候出现
- 高压操作路径上，动画成本恒定为 0
- 性能可控：装饰层永远可以整层卸载

代价：
- 两套动效代码要维护（功能层与装饰层不能共用实现）
- 用户可能开了「华丽」后在收作业时也被动画拖慢——通过「对账台强制降级」兜底

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 全站统一华丽 | 40 次标记 × 每次多 200ms = 8 秒纯等待，且打断节奏 |
| 完全不做动效 | 丢掉产品性格，且用户明确要 |
| 只做开关不做分层 | 开关是全局的，会把「标记反馈」一起关掉，反而更差 |
