## 0. 先把产品说清楚

DEEP 的首页不是数据可视化大屏，而是 **ShenFall 的个人行动中心**。

五类核心对象：

| 核心对象 | 首页要回答的问题 | 主动作 |
|---|---|---|
| 待办 | 我现在该做什么？ | 完成、继续处理、新建 |
| 时间 | 接下来什么时候截止或开始？ | 查看时间轴、进入来源 |
| 作业 | 哪些作业正在收集，进度怎样？ | 查看作业详情 |
| 资料 | 什么待整理、待发布或刚更新？ | 收录、整理、发布、复制链接 |
| 通知 | 哪条老师通知还没处理？ | 阅读原文、拆解时间与任务 |

**点名 / 对账是作业详情中的二级功能。** 它可以在紧急作业卡中提供入口，但不在首页展示姓名矩阵，不与五类核心对象争夺首屏。

### 从首页移除

- 资料热度、下载排行、资源趋势、健康分、抽象进度分。
- 没有下钻动作的统计卡和为了凑四宫格的数字。
- 与行动无关的「最近动态」流水墙。
- 占据首屏的大 DEEP 字标、独立的大块空轨道装饰卡。
- `Status / Progress / Health / Next Node / Resource Heat` 等抽象英文占位。
- 生成图里的灰色横线假文字、伪造百分比和伪造业务数据。

## 1. 核心对象如何连起来

首页不是五个互不相干的工具，而是同一条工作流：

```text
老师通知 ──拆解──> 待办 + 时间节点
作业清点 ──产生──> 最近 DDL + 待办
本地资料 ──整理──> 发布资料 ──完成──> 对应待办归位
个人待办 ──可选──> 放入个人时间轴
```

- 每条待办可以没有来源，也可以链接到一条通知、一项作业或一份资料。
- 时间节点显示来源，点击能回到原文、作业或日程，而不是进入一张孤立图表。
- 完成动作留在原处显示完成态并提供撤销；刷新或下次进入后再归入已完成，避免手指失去位置。

## 2. 管理员桌面端 `/dashboard`

### 2.1 页面结构

设计基准 1440px，左侧 64px 导航，顶部 56px，内容最大宽 1440px，12 列网格，卡片间距 16–20px。

```text
┌ 导航 ┬ 顶栏：DEEP · 2026 秋 · 计科 2 班            搜索       头像 ┐
│ 看板 ├─────────────────────────────────────────────────────────┤
│ 待办 │  11 月 22 日，周日                         [ + 记待办 ]  │
│ 作业 │  3 项待办 · 最近截止 23:59                              │
│ 资料 │ ┌──────────── 8 列：现在要做 ────────────┐ ┌ 4 列：接下来 ┐│
│ 通知 │ │ 今天 / 稍后 / 无时间 三组行动清单        │ │ 未来 48 小时  ││
│ 日程 │ │ 每条含来源、时间、主动作                  │ │ 时间轴 + 当前线││
│      │ └───────────────────────────────────────┘ └─────────────┘│
│ 更多 │ ┌──── 4 列：进行中的作业 ────┐┌──── 4 列：资料 ────┐┌ 4 列：通知 ┐│
│      │ │ 课程、DDL、已收人数、查看    ││ 待整理/待发布/最近更新││ 待拆解列表  ││
│      │ └───────────────────────────┘└───────────────────┘└───────────┘│
└──────┴─────────────────────────────────────────────────────────┘
```

轨道线稿只作为页头右侧低对比背景或加载器出现，不单独占一张大卡。页头最大 28px；DEEP 只在顶栏作为小字标。

### 2.2 A. 现在要做（主卡，8 列）

这是首页视觉重心，不是统计数字。

每行结构：

```text
○  发布计网期末复习提纲              [ 资料 ]  今天 21:00      去发布 →
○  确认操作系统实验课时间变更        [ 通知 ]  明天 12:00      看原文 →
○  整理数据结构第 7 章课件           [ 资料 ]  无时间           去整理 →
```

| 元素 | 规格 |
|---|---|
| 分组 | `已逾期`、`今天`、`接下来`、`无时间`；无内容的分组不占位 |
| 行内容 | 完成按钮、标题、来源标签、时间、一个主动作 |
| 排序 | 逾期 → 今天 → 接下来 → 无时间；同组按时间升序 |
| 数量 | 默认最多 5 条，底部 `查看全部 N 条` |
| 完成 | 原地打勾、文字退为次级色，Toast 提供撤销；不立即跳走 |
| 新建 | 页头 `+ 记待办` 只需标题即可保存，时间与来源可后补 |
| 空态 | `今天没有待办。可以整理一份资料，或早点休息。` + 两个可选动作 |

### 2.3 B. 接下来（4 列）

不是完整日历，也不是图表，是未来 48 小时的紧凑时间轴。

```text
接下来 48 小时                              查看日程 →
今天
21:00  发布计网复习提纲          [ 资料 ]
23:59  数据结构 · 作业 4 截止    [ 作业 ]
明天
12:00  操作系统实验课            [ 日程 ]
18:00  计网实验报告截止          [ 作业 ]
──────── 现在 20:42 ────────
```

- 当前时间线只在有意义时出现，不遮挡事件。
- 逾期事项归入「现在要做」，不在时间轴重复制造红色。
- 点击条目进入来源；右上角进入完整日程。
- 空态：`未来 48 小时没有安排`，保留 `新建日程`。

### 2.4 C. 进行中的作业（4 列）

```text
进行中的作业                            查看全部 →
数据结构 · 作业 4
今晚 23:59 · 已收 39/40                 查看 →
操作系统 · 作业 2
明天 12:00 · 已收 32/40                 查看 →
```

- 只展示进行中或最近结束且仍需收尾的 2–3 项。
- 人数是行动线索，点击后进入作业详情；首页不显示完成率饼图。
- 紧急项可出现 `进入对账`，作为明确的二级功能快捷入口。
- 空态：`现在没有正在收集的作业` + `新建作业`。

### 2.5 D. 资料（4 列）

资料卡只呈现需要处理与最近变化，不做热度分析。

```text
资料                                    打开资料库 →
待整理  2    待发布  1

最近更新
计网期末复习提纲 v3          22:18      复制链接
数据结构第 7 章课件          昨天       继续整理

[ 收录资料 ]
```

- `待整理`：缺少课程、类型或标题等必要信息。
- `待发布`：已整理但仍只在本地；点击进发布设置。
- `最近更新`最多 2 条，动作与状态对应，不固定都显示复制链接。
- 空态：`资料库还是空的` + `收录第一份资料`。

### 2.6 E. 通知（4 列）

```text
通知                                    查看全部 →
● 王老师：实验课改到下周三……
  识别到 1 个时间 · 待确认              拆解 →
● 李老师：作业提交方式有变……
  未拆解                                拆解 →
```

- 未处理通知用 `●`；已处理不在首页重复出现。
- 显示老师、原话摘要、拆解状态，不在卡片上塞完整原文。
- 疑似时间用琥珀虚线与 `待确认`，点击回到原文锚点。
- 空态：`通知都处理完了`。

## 3. 管理员手机端 `/dashboard`

手机端按行动顺序重排，不缩小桌面 12 列网格。

```text
11 月 22 日，周日                              头像
3 项待办 · 最近截止 23:59               [ + ]

┌ 最近截止 ──────────────────────────────┐
│ 数据结构 · 作业 4                       │
│ 今晚 23:59 · 已收 39/40      查看作业 → │
└────────────────────────────────────────┘

现在要做                                  全部 3 条 →
○ 发布计网期末复习提纲      今天 21:00    去发布
○ 确认实验课时间变更        明天 12:00    看原文
○ 整理第 7 章课件           无时间        去整理

接下来
21:00  发布复习提纲
23:59  数据结构作业截止

[ 作业 2 项进行中 ]  [ 资料 2 项待整理 ]
[ 通知 2 条待拆解 ]  [ 日程：查看完整安排 ]

底部：看板       作业       资料       我的
```

- 待办列表优先于所有统计与装饰；手机首屏至少能看到第一条真实待办。
- 底部模块入口显示的是待处理数量，不是热度或抽象分数。
- 点名仍通过 `作业 → 作业详情 → 对账` 进入；紧急作业可省一次点击。
- 所有可点区域 ≥48px；完成待办后提供可见撤销。

## 4. 用户资料端 · 个人资料空间

资料端保持公开、免登录、搜索优先，不展示热度、下载排行或同学行为数据。

```text
[真实头像]  ShenFall / DEEP

ShenFall 的资料空间
课件、提纲与真题，按课程整理好，找到就能直接下载。

[ 搜索课程、章节或资料名称                         ]

[ 全部课程 ]  [ 计算机网络 ]  [ 数据结构 ]  [ 操作系统 ]

精选资料 · 由我人工置顶
PDF  计网期末复习提纲 v3        12 页 · 2.4MB · 11-22
PDF  2025 期末真题              8 页 · 1.1MB · 11-20

最近更新
ZIP  数据结构第 7 章课件        11-22

关于这个空间
由 ShenFall 持续整理。文件失效或找不到资料，在群里 @我。
```

- 「精选」必须明确是人工置顶，不能伪装成算法推荐。
- 个人识别来自真实头像、「深」、DEEP、整理者文案与少量轨道线稿。
- 个人主页或联系方式只放愿意公开的链接，不做社交动态、粉丝、点赞和评论。
- 文件卡展示格式、名称、页数/体积与更新日期；点卡片直接下载。
- 搜索无结果、资料下线与微信下载拦截沿用既有文案与兜底。

## 5. 混元概念稿与参考素材怎么用

### 5.1 DEEP-001 当前稿的取舍

| 保留 | 修改或删除 |
|---|---|
| 深空底、蓝金关系、细线轨道 | 巨大 DEEP 字标缩小到顶栏 |
| 卡片比例、较充分留白 | 独立空轨道大卡删除，改为页头轻背景 |
| 细边线与克制圆角 | Status / Progress / Health / 热度 全部删除 |
| 右侧最近节点的大致位置 | Next Node 改为真实「接下来」时间轴 |
| 左侧窄导航 | Resource Heat 改为「资料」行动卡 |
| 整体安静、低亮度的材质 | 灰线占位全部替换为真实中文信息层级 |

**当前稿只作为视觉壳参考，不再作为后续手机端和资料端的信息架构锚点。**

### 5.2 用户素材的使用边界

- `ref-01`：只取精密网格、刻度和点阵纪律；不要密集英文海报字与视觉噪声。
- `ref-02`：只取同心圆和几何嵌套；不要直接画成魔法阵。
- `ref-03 / 04 / 05`：只取细金线、放射线、少量星点；避免图腾、捕梦网、塔罗与占星气质。
- `ref-06`：只取轨道构图与同心环；不照搬多彩靶心、游戏准星或紫色霓虹。
- 所有带水印、素材站文字的图只作风格参考，不直接贴入产品或生成结果。

## 6. 加载、空态与异常

- 首次打开看板使用 Orbit Plotter；已有缓存时先显示旧内容，各卡局部更新，不全屏阻断。
- 后续刷新使用卡片骨架，不反复播放品牌加载动画。
- 加载动画不显示伪造百分比，数据就绪立即退出。
- 每个核心模块有独立空态，不让一张空卡拖白整个看板。
- 本地数据读取失败时显示可读错误与重试，不用通用 `系统繁忙`。
- 离线时保留本地待办与作业操作；手机看板快照显示更新时间，不假装实时。

## 7. 后续执行硬要求

### 对视觉 / 生图智能体

1. 先读本文件，再看 17 的视觉语言；不得只拿 DEEP-001 当前稿继续派生。
2. 概念图必须体现五类真实内容：待办、时间、作业、资料、通知。
3. 禁止热度、健康分、抽象进度、空轨道大卡、灰色横线假文字。
4. 概念图只用于方向，中文正文、数字、按钮和图表最终由 HTML 实现。
5. 参考图只提取语言，不带入水印、素材站文字和神秘学符号。

### 对前端实现

1. 先接真实数据与空态，再加轨道背景、透明材质与动效。
2. 每张卡都有明确来源、主动作与目标路由；没有动作的卡片不上首页。
3. 待办完成可撤销，点名坐标恒定，资料发布不自动上传。
4. 看板桌面与手机共享内容优先级，不共享同一套压缩布局。
5. 减少动态模式下所有信息仍可读取与操作。

## 8. 验收清单

- [ ] 打开首页 3 秒内能回答：现在做什么、最近什么时候截止。
- [ ] 待办、时间、作业、资料、通知都在首页有真实内容或合理空态。
- [ ] 首页没有热度、健康分、下载趋势、伪造进度与流水墙。
- [ ] 点名不在首页，紧急作业最多两次点击进入对账。
- [ ] 每条待办能完成并撤销，来源明确，点击可回到来源。
- [ ] 资料卡只呈现待整理、待发布、最近更新与有效动作。
- [ ] 通知卡能回到原文并确认拆解时间。
- [ ] 用户资料端保留个人识别，但搜索到下载仍不超过两次点击。
- [ ] 概念图与真实实现均不含灰线假文字和抽象英文占位。
- [ ] 所有素材无水印、无素材站文字、不过度神秘学化。
