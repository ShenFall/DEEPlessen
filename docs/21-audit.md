# 21 存量审计报告 v1

> 2026-11-23。本报告基于**仓库里的真实代码**，不是对描述的复述。
> 目的：在三端目标下判断"哪些能留、哪些要改、哪些要重做"。

## 0. 先说一件必须先解决的事：技术栈不一致

任务书里的约定与仓库实际不符。这不是笔误，它会决定后面所有文档是否作废。

| 项 | 任务书约定 | 仓库实际 | 差异 |
|---|---|---|---|
| 前端框架 | Vue 3 | **React 18.3.1** | 全量重写 |
| 样式方案 | Tailwind CSS | **原生 CSS + CSS 变量**（`tokens.css`） | 全量重写 |
| 动画 | GSAP | 原生 CSS 动画（少量） | 需要引入 |
| 拖拽 | vuedraggable | 未实现 | Vue 专属库，React 不可用 |
| 后端 | Node.js/Express + SQLite | **无后端**（无 `server/` 目录） | 从零搭建 |
| 数据存储 | SQLite | **IndexedDB（Dexie v4）** | 从零迁移 |
| 文件存储 | 未指定 | File System Access API（本地目录 `I:\DataSystem`） | 需重新设计 |
| 部署 | 未指定 | 静态站点 + PWA，无服务器 | 需增加服务器与运维 |

**已写好的代码量**：11 个业务模块、约 3.3k 行 TS/TSX、4 张表、5 个界面、可构建、可离线。

**结论**：若按 Vue + Express + SQLite 执行，**现有代码 100% 不能复用**，等于重做；且会失去当前最大的两个优点——**零服务器成本**与**离线可用**。

### 两条路，需要用户拍板

| | 路线 A：保持现状（React + 本地优先） | 路线 B：改按任务书（Vue + Express + SQLite） |
|---|---|---|
| 已完成部分 | 全部保留 | 全部作废，重写 |
| 学生端 | 需要对象存储 + 静态页（M3 未完成） | 后端天然支持，但要有服务器 |
| 权限 | 无（单机，无登录） | 需要写（admin/student） |
| 离线 | 可用 | 不可用（依赖网络） |
| 成本 | 剩余 M3 约 5–8 天 | 约 3–4 周（含后端、部署、迁移） |
| 风险 | 学生端分发依赖第三方存储 | 服务器运维、备案、费用 |

**建议**：走 A，把"三端"实现为"一套本地管理端 + 一份静态学生门户"，不引入服务器。
若坚持 B，本报告第 2 节的"复用"结论全部改为"重做"，需要重新出规格。

## 1. 四项存量审计

### 1.1 点名 / 对账

- **判定**：🔧 改造复用（逻辑 100% 保留，只调样式）
- **归属端**：A（桌面）+ B（手机）
- **现状**：`features/reconcile/ReconcileScreen.tsx`，4 列网格、点标记、长按 350ms 恢复、220ms 淡出、写 Dexie、只读态（已结束）、视图跟随筛选、`⋯` 菜单（导入/复制/结束/重置）。
- **改造点**：
  1. 桌面端需要 8–10 列矩阵（当前固定 4 列）
  2. 视觉换新 Token（工作台仍守细线与 ≤8px 圆角）
  3. 补"撤销"？—— 用户已明确否决，改长按恢复，**保持现状**
- **不可动**：标记/恢复的时序、`submissions` 表结构、只读判定

### 1.2 资料库 + 搜索

- **判定**：🔧 改造复用（数据与文件层保留，交互补充）
- **归属端**：A（管理）+ C（学生只读）
- **现状**：`features/library/LibraryScreen.tsx` + `fs/index.ts` + `storage/local.ts`
  - 已实现：选库根、拖入收录、sha1 去重、文件名清洗、按课程分组、类型筛选（讲义/文档/表格/图片/压缩代码）、最近/名称排序、发布到 `publish/<slug>/manifest.json`、已发布列表、复制 slug、两段确认下架
- **改造点**：
  1. **分类体系**：现在按"课程 + 扩展名"分类，缺"按用途"（讲义/作业/复习）与标签
  2. **C 端展示**：manifest 已有，缺渲染页（M3 的 3.10）
  3. 搜索只匹配文件名与课程名，缺内容/标签搜索
- **不可动**：`Material` 与 `Publish` 的数据形状、去重策略、库目录结构

### 1.3 手机端 UI

- **判定**：🔧 改造复用（结构可用，视觉需统一）
- **归属端**：B
- **现状**：单列、`max-width: 560px`、底部操作条吸附、`env(safe-area-inset-*)` 已处理、深/浅主题变量
- **改造点**：
  1. 缺**底部导航**（看板/作业/资料），现在是页内跳转
  2. 断点 1024px 处 8/4 分栏偏挤（已记录）
  3. 与桌面端共用组件需抽到 `src/ui`

### 1.4 主页看板

- **判定**：✅ 结构可复用，🔧 视觉待重做
- **归属端**：A + B（同一套结构，密度不同）
- **现状**：`features/dashboard/DashboardScreen.tsx`，六块：状态条 / 现在要做（由真实清点推导）/ 接下来（时间轴）/ 作业数字 / 资料 / 左导航
- **改造点**：
  1. 视觉（材质、渐变、动效）由设计侧出稿
  2. 待办 / 通知 / 日程三块**无数据来源**，暂为导航占位
  3. 桌面 12 列栅格未使用（现在是 8/4 + 6/6）
