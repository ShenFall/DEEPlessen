# 15 M3 施工计划：资料库与分发

> 目标：让"资料发给全班"这件事从「一个个发微信」变成「发一个链接」。
> 决策依据：ADR-0001（学生端公开只读）、ADR-0008（本地库 + 对象存储）。

## 0. 前提（先对齐，错了整段白做）

| 项 | 假设 | 如果不对 |
|---|---|---|
| 使用人 | 只有你一个，无多人协作 | 需要账号体系，M3 全部推翻 |
| 班级规模 | 30 人量级 | 上百人要考虑分页与限流 |
| 文件规模 | 每学期 1–3 GB，单文件 < 100 MB | 超过要分片上传 |
| 部署 | 不租服务器；本机 Windows + 对象存储 | 有服务器可省掉 Tauri |
| 网络 | 学生手机能打开公网 HTTPS 页面 | 只能内网分发，等于放弃 |

**不做**：在线预览、版本管理、权限分级、学生上传、批量替换。

## 1. 两条技术路线，先选一条

| | A. Tauri 壳 | B. 浏览器 File System Access |
|---|---|---|
| 读写本地库 | 原生，稳 | 只能 Chrome/Edge，每次重开要重新授权 |
| 监听微信下载目录 | 能 | 不能 |
| 安装成本 | Rust + MSVC + WebView2，约 2–4 GB 下载 | 0 |
| 国内网络风险 | **高**（Rust 源、MSVC 安装包都慢） | 无 |
| 打包分发 | 需要签名，SmartScreen 会拦 | 不需要 |

**建议**：先做 3.1 环境预检。若 Rust 工具链能在 1 小时内装好，走 A；否则走 B，并把"监听目录"推迟到以后。**不要在没有工具链的情况下先写 20 个 TS 文件**。

## 2. 数据模型（先定，后面全依赖它）

```ts
// 新增两张表，students / assignments / submissions 不动
Material {
  id: string
  course: string          // 数据结构
  title: string           // 第 4 章 图与遍历
  kind: 'slide' | 'sheet' | 'code' | 'other'
  file: string            // 库内相对路径 materials/ds/xxx.pdf
  size: number
  sha1: string            // 去重 + 完整性
  createdAt: string
}

Publish {
  id: string              // slug，对外唯一
  materialIds: string[]
  state: 'local' | 'uploading' | 'published' | 'offline'
  urls: Record<string, string>   // materialId -> 对象存储 key
  expiresAt?: string
  createdAt: string
}
```

原则：**Material 永远指向本地文件**；Publish 只是"哪些文件对外可见"的一张表。删 Publish 不动 Material。

## 4. 切成三段交付，每段都能停

| 段 | 包含 | 交付后能做什么 | 大概 |
|---|---|---|---|
| **M3a 库** | 3.1–3.7 | 资料能进库、能分类、能搜，**但还不能发给别人** | 3–5 天 |
| **M3b 分发** | 3.8–3.11 | 发链接，学生手机能下载 | 3–4 天 |
| **M3c 收尾** | 3.12–3.15 | 文案、下架、验收、备份 | 1–2 天 |

**每段结束都可以停**，不会留半截功能。M3a 做完即使不分发，你的资料也已经有序了。

## 5. 风险与兜底

| 风险 | 影响 | 兜底 |
|---|---|---|
| Rust 工具链装不上 | A 路线走不通 | 走 B（浏览器 FS Access），功能砍掉"监听目录" |
| R2 注册/实名卡住 | 无法分发 | 先用 GitHub Releases 挂文件，链接丑但能用 |
| 预签名密钥泄露 | 别人能往你桶里写 | 密钥只在本机进程内存，不进构建产物；桶开只写不读的受限 token |
| 学生端在国内打不开 | 分发失败 | 学生端静态页优先部署在国内可访问的平台 |
| 微信内置浏览器拦下载 | 学生下不了 | 提供"复制链接到浏览器打开"的文案；文件用 `Content-Disposition: attachment` |
