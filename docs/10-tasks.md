# 10 任务拆解与分步实现

> 原则：**每个里程碑结束时，你都能真的拿它用一次**，而不是"完成了 60% 的代码"。

## 为什么纵向切，不横向切

教科书做法是「先做完数据层，再做 UI，再做接口」。这个项目不能这么切，原因有三：

1. 对账台是全项目唯一**没被验证过的交互**。先做两周数据层，等于把一个可能不好用的交互推到三周后才发现。
2. 你是一个人，中间一定会中断。横向切的话，中断时手上是一堆永远跑不起来的半成品。
3. 这东西的价值在「真的用了一次」。第一周就能收一次作业，比第五周能收，价值差一个数量级。

所以：**每一刀都切到底**——从界面到存储到真实使用，一次切穿一个功能。

## 规模标记

以「一个有效工作块 = 半天（3–4 小时不被打断）」为单位：

- **S** = 1 个块
- **M** = 2–3 个块
- **L** = 4–6 个块

---

## M0 · 骨架与假数据

**目标**：在对账台上敲通一次标记，证明这个交互成立。其余全部是假的。

| # | 任务 | 规模 |
|---|---|---|
| M0-1 | 工程初始化：Vite + TS + React + 路由。**不引 UI 组件库**——它的默认圆角和阴影会绑架视觉 | S |
| M0-2 | 设计令牌层：CSS 变量（色/字/间距/圆角）、字体栈、`data-theme="void"` | S |
| M0-3 | 硬编码 40 人 + 1 个作业的假数据 | S |
| M0-4 | 对账台静态版：标题 / 进度条 / 命令行 / 队列 / 8×5 矩阵 | M |
| M0-5 | 命令行匹配 v0：拼音首字母 + 姓名包含，回车标记，`Z` 撤销 | M |

**出口**：敲 `cz` 能标掉陈知远，格子变暗且不移位，视觉与设计稿一致。不持久化也接受。
**不做**：真实存储、导入、权限、路由守卫。

---

## M1 · 数据落地

**目标**：花名册进得来、存得住、换班能重来。

| # | 任务 | 规模 |
|---|---|---|
| M1-1 | Dexie schema（cohort/student/course/assignment/submission）+ 版本迁移 | M |
| M1-2 | CSV/TSV 解析 + 编码嗅探（Excel 导出常是 GBK） | M |
| M1-3 | 列映射 UI + 记住映射 | S |
| M1-4 | 导入预览三态（绿/黄/红）+ 重名阻断 | M |
| M1-5 | 合并导入：按学号对齐，消失的人标 `inactive` | M |
| M1-6 | 导出 JSON / CSV（防锁定） | S |

**出口**：导入你真实的 40 人花名册，标 5 个人，**刷新浏览器还在**；再导一次不会重复。
**不做**：xlsx 解析（先要求存成 CSV）、作业 CRUD。

## M2 · 收作业闭环 ★核心

**目标**：这个项目值不值得做，看这一刀。

| # | 任务 | 规模 |
|---|---|---|
| M2-1 | 作业 CRUD + DDL + 状态机（open/reconciling/closed） | M |
| M2-2 | 拖文件识别：File API → 文件名归一化 → 匹配 | M |
| M2-3 | 别名表写入与命中（匹配成功即记住那个写法） | S |
| M2-4 | 证据流 + 撤销栈（20 步）+ 时间戳 | M |
| M2-5 | 收尾态换挡（剩 ≤2 人）+ 收齐落金 | S |
| M2-6 | 今日页：最近 DDL + 欠交汇总 | M |
| M2-7 | 手动勾选 + 拖框多选（线下收纸质用） | S |

**出口**：**拿它真的收一次作业**。中途关掉页面、去吃饭、回来接着标。
**不做**：统计、周报、多人协作。

> 这一刀做完，如果它没让你觉得"比翻群聊快"，就停下来重新想，别往下走。

## M3 · 资料与学生端

**目标**：把"总有人来问我要"这件事从你的时间线上删掉。

| # | 任务 | 规模 |
|---|---|---|
| M3-1 | R2 桶 + 预签名直传（不经应用服务器） | M |
| M3-2 | 批量上传 + 文件名清洗 + 自动打标 | M |
| M3-3 | 发布设置：公开/口令/有效期 + 随机 slug | S |
| M3-4 | 学生端课程页（静态 + 只读 API，浅色皮肤） | L |
| M3-5 | 部署（Pages）+ 自定义域 + `noindex` | S |
| M3-6 | 群文案生成（链接 + 口令，这个还有用） | S |

**出口**：链接发到群里，**至少 5 个同学真的下载成功**，且没有一个人问你"这个怎么用"。
**不做**：在线预览、版本树、下载人追踪。

## M4 · 通知与日程

**目标**：老师一段乱糟糟的话，变成时间轴上的三张卡。

| # | 任务 | 规模 |
|---|---|---|
| M4-1 | 通知收件箱 + 粘贴框 + 原文保存 | M |
| M4-2 | LLM 解析（边缘函数 + JSON schema + 3s 超时降级为手动） | L |
| M4-3 | 原文锚点高亮与回跳 | M |
| M4-4 | 任务卡 → 时间轴 + 与作业卡关联 | M |
| M4-5 | 周视图 + 图层开关（我的/班级）+ 冲突提示 | L |

**出口**：拿一条真实的老师通知，能拆对 80%，错的你能一次改对，且改完它记住了。
**不做**：自然语言"提醒我"、日历双向同步。

## M5 · 外观与动效

**目标**：把 09-appearance 落地，让这东西看起来是你的。

| # | 任务 | 规模 |
|---|---|---|
| M5-1 | 主题令牌扩展：色彩/材质/密度/字体四组可覆盖 | M |
| M5-2 | 壁纸 + 可读性守门（自动对比度 + 强制 scrim） | M |
| M5-3 | 5 套预设 + 壁纸自动取色 | M |
| M5-4 | 动效三层实现 + 三档预设（静默/标准/华丽） | L |
| M5-5 | 偏好持久化 + `prefers-reduced-motion` 降级 + FPS 自动降档 | S |

**出口**：换成自己的图当壁纸，**正文对比度仍然合规**；开"华丽"后对账台依然不卡、不晃。
**不做**：动效编辑器、主题市场、自定义圆角。

## 依赖关系

```
M0 ──▶ M1 ──▶ M2 ──┬──▶ M3 ──▶ M4
                   │
                   └──▶ M5（可与 M4 并行，或等 M4 后）
```

- M1 依赖 M0 的令牌层（不然要返工样式）
- M2 依赖 M1 的真实花名册（假数据也能做，但出口验收要真数据）
- M3 可以独立推进（不依赖对账台），**如果哪天心情不好想换换脑子，就去做 M3**
- M5 必须最后，因为它要覆盖前四个里程碑的所有界面

## 节奏建议

按每周 8–10 小时（两个有效块）估算：

| 里程碑 | 块数 | 约 |
|---|---|---|
| M0 | 5 | 1 周 |
| M1 | 6 | 1.5 周 |
| M2 | 8 | 2 周 |
| M3 | 8 | 2 周 |
| M4 | 9 | 2–2.5 周 |
| M5 | 9 | 2–2.5 周 |
| 合计 | 45 | **约 11 周** |

但 M2 结束（约 4.5 周）时它就已经能救命了。M3–M5 是"更好用"和"更像你"。

## 现在就能做的三件事

1. `M0-1` + `M0-2`：建工程、铺令牌。一个晚上，做完就能看到一个深空底色的空页面。
2. `M0-4`：把对账台的静态壳搭出来，贴假数据。**先不要写逻辑**，只摆位置。
3. 拿真实花名册试一遍 `M1-2/M1-4` 的思路：你那份 Excel 到底长什么样、表头叫什么、有没有合并单元格。这一步不用写代码，只需要打开文件看一眼——它会改变 M1 的三个任务。

## 用 GitHub 追踪

- 每个 `M#-#` 一条 issue，标题直接用上面表格里的名字
- label：`M0`…`M5` + `core` / `infra` / `polish`
- M2 的所有 issue 加 `core` 并置顶，其余按里程碑排序
- **一个里程碑的出口标准没达成，不开下一个**。这条纪律比任何技术选型都重要。

## 最容易烂尾的三种走法

| 走法 | 后果 |
|---|---|
| 先把 5 个模块的页面都画出来 | 全是空壳，没有一个能用，两周后失去兴趣 |
| 先做外观和动效 | 好看的空盒子，收作业还是靠群聊 |
| 一开始就做多班级/多角色/同步 | 权限模型吃掉全部时间，核心交互没验证 |
