# 10 任务拆解与分步实现

> 原则：**每个里程碑结束时，你都能真的拿它用一次**，而不是"完成了 60% 的代码"。

## 为什么纵向切，不横向切

教科书做法是「先做完数据层，再做 UI，再做接口」。这个项目不能这么切，原因有三：

1. 对账台是全项目唯一**没被验证过的交互**。先做两周数据层，等于把一个可能不好用的交互推到三周后才被发现。
2. 你是一个人，中间一定会中断。横向切的话，中断时手上是一堆永远跑不起来的半成品。
3. 这东西的价值在「真的用了一次」。第一周就能收一次作业，比第五周能收，价值差一个数量级。

所以：**每一刀都切到底**——从界面到存储到真实使用，一次切穿一个功能。

**v0.5 起，每一刀都从手机切。** 桌面版是之后补的第二层皮肤（见 [ADR-0006](decisions/0006-mobile-first.md)）。

## 规模标记

以「一个有效工作块 = 半天（3–4 小时不被打断）」为单位：

- **S** = 1 个块
- **M** = 2–3 个块
- **L** = 4–6 个块

## M0 · 手机骨架与假数据

**目标**：在真机上点通十个标记，证明这套拇指交互成立。其余全是假的。

| # | 任务 | 规模 |
|---|---|---|
| M0-1 | 工程初始化：Vite + TS + React + 路由。**不引 UI 组件库**——它的默认圆角和阴影会绑架视觉 | S |
| M0-2 | 令牌层：两套主题（深空 / 旧纸）+ 跟随系统深浅切换 | S |
| M0-3 | 移动优先断点体系（<720 / 720–1100 / >1100）+ 安全区内边距 | S |
| M0-4 | 硬编码 40 人 + 1 个作业的假数据 | S |
| M0-5 | 手机对账台静态：顶栏 / 进度条 / 筛选 chip / 4 列网格 | M |
| M0-6 | 触控基础：48px 目标、`touch-action`、点击与滚动的判定（位移<8px 且 <300ms） | S |
| M0-7 | 假持久化（localStorage）+ 撤销 toast + 命中震动 | M |

**出口**：**iPhone / Android 真机**上（不是 DevTools 模拟），单手点掉 10 个人，撤销 1 次，滚回顶部再点 1 个。
**不做**：真存储、Excel、PWA、桌面布局。

> 这一关的意义：如果 4 列网格在真机上让 40 人显得太挤、或者拇指够不到第 4 列，现在改还来得及——这是全项目最便宜的返工点。

## M1 · 数据落地（Excel + 离线）

**目标**：真实花名册进得来、存得住；教室断网也能标。

| # | 任务 | 规模 |
|---|---|---|
| M1-1 | Dexie schema（cohort/student/course/assignment/submission）+ 版本迁移 | M |
| M1-2 | Excel 解析：SheetJS（CDN 0.20.3 版）**动态 import**，不占首屏 | M |
| M1-3 | 五个坑：学号科学计数法拦截、合并单元格前向填充、表头行探测、多 sheet 选择、姓名清洗 | L |
| M1-4 | 列映射 UI + 记住映射 | S |
| M1-5 | 导入预览三态（绿/黄/红）+ 重名阻断 | M |
| M1-6 | 合并导入：按学号对齐，消失的人标 `inactive` | M |
| M1-7 | PWA：manifest + service worker + 离线壳缓存 | M |
| M1-8 | 拼音索引（pinyin-pro）+ 导出 JSON 备份 | S |

**出口**：把**真实花名册**（29 行）扔进去 → 得到 **28 人在用 + 1 条离班**；然后开飞行模式标记 3 个人，刷新页面还在，且**没有弹出任何网络错误**。
**不做**：CSV 编码嗅探（P1）、OCR。

## M2 · 手机收作业闭环 ★核心

**目标**：这个项目值不值得做，看这一刀。

| # | 任务 | 规模 |
|---|---|---|
| M2-1 | 作业 CRUD + DDL + 状态机（open/reconciling/closed） | M |
| M2-2 | 网格标记 + **自动前进**（可关）+ 震动/视觉反馈 | M |
| M2-3 | 撤销 toast（3.5s）+ 时间戳 + 来源证据 | S |
| M2-4 | 匹配引擎 v1：精确 → 别名 → 拼音 → 包含；匹配不上弹「这是谁」 | L |
| M2-5 | 从微信导入：系统文件选择器 + 文件名匹配 | M |
| M2-6 | 收尾态换挡（剩 ≤2 人）+ 收齐落金 | S |
| M2-7 | 今日页（手机版） | M |

**出口**：**站着、用一只手、在真机上收一次真作业**。中途锁屏、回微信、再回来，状态不丢。
**不做**：统计、批量补录、桌面矩阵。

> 这一刀做完，如果它没让你觉得"比翻群聊快"，就停下来重新想，别往下走。

## M5+ · 桌面增强（可选）

手机跑顺了以后，桌面端才值得投入。以下**不属于核心路径**：

| # | 内容 | 何时做 |
|---|---|---|
| +1 | 8×5 矩阵视图（桌面） | 需要一次看全 40 人时 |
| +2 | 命令行 `deep:~/hw4$` + 键盘快捷键 | 想批量补录、不想碰鼠标时 |
| +3 | 批量粘贴已交名单（补录） | 白天收了纸质，晚上追认 |
| +4 | 欠交榜、资料热度统计 | 期末跟老师交代时 |

**注意**：命令行从"核心交互"降级为"可选工具"。手机网格才是默认路径。

## 依赖关系

```
M0 ──▶ M1 ──▶ M2 ──┬──▶ M3 ──▶ M4
                   │
                   └──▶ M5 ──▶ M5+（可选）
```

- M1 依赖 M0 的令牌与断点（不然要返工两套样式）
- M2 依赖 M1 的真实花名册（假数据能开发，但出口验收要真数据）
- M3 可独立推进——**哪天不想碰对账台就去做 M3**，它跟核心解耦
- M5 必须最后，它要覆盖前面所有界面
- M5+ 随时可砍，砍了不影响使用

## 节奏建议

按每周 8–10 小时（两个有效块）估算：

| 里程碑 | 块数 | 约 |
|---|---|---|
| M0 | 6 | 1.5 周 |
| M1 | 9 | 2 周 |
| M2 | 8 | 2 周 |
| M3 | 8 | 2 周 |
| M4 | 9 | 2–2.5 周 |
| M5 | 9 | 2–2.5 周 |
| 合计 | 49 | **约 12 周** |

**再预留 1–2 周给手机特有的坑**：真机调试、iOS 的文件选择行为、PWA 安装流程、安全区适配。这些在模拟器上全测不出来。

M2 结束（约 5.5 周）时它就能救命了。

## 现在就能做的三件事

1. **拿真机试一下 4 列网格**：把 40 个名字排成 4 列，看你拇指能不能舒服够到第 4 列。够不到就改 3 列——现在改是免费的。
2. **把真实花名册扔进任何在线 xlsx 查看器**：看表头在第几行、有没有合并单元格、学号是不是被转成了科学计数法。这一步不用写代码，但会改掉 M1 的三个任务。
3. `M0-1` + `M0-2`：建工程、铺两套令牌。一个晚上能看到深色和浅色两个版本的空页面。

## 用 GitHub 追踪

- 每个 `M#-#` 一条 issue，标题直接用表格里的名字
- label：`M0`…`M5` + `core` / `infra` / `polish` + `mobile`
- M2 的所有 issue 加 `core` 并置顶
- **一个里程碑的出口标准没达成，不开下一个**

## 最容易烂尾的四种走法

| 走法 | 后果 |
|---|---|
| 先把 6 个模块的页面都画出来 | 全是空壳，没有一个能用，两周后失去兴趣 |
| 先做外观和动效 | 好看的空盒子，收作业还是靠群聊 |
| 一开始就做多班级/多角色/同步 | 权限模型吃掉全部时间，核心交互没验证 |
| **只在 DevTools 里测手机** | 真机上拇指够不到、震动不生效、PWA 装不上，全部白做 |
