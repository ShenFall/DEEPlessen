# 25 发布到公网（一页说明）

> 2026-11-23。给"改了资料，怎么让同学看到"这件事。
> 应用内也有同一份说明：资料页 → 发布到公网 → 怎么做。

## 一句话

**导出 → 打包 → 拖进 Cloudflare。** 三步，两分钟。

## 步骤

### 1. 导出（在应用里）

资料页 → 「已发布」右侧 → **导出学生门户**
生成 `I:\DataSystem\portal\`

### 2. 打包

把 `portal` **里面的内容**压成 zip（`index.html` 必须在最外层）。

> 不会压就把 `I:\DataSystem\portal` 路径发给总工，由它打好放桌面。

### 3. 上传

1. 浏览器打开 Cloudflare → **Workers & Pages** → 项目 `deep-portal`
2. 点 **Create new deployment**
3. 环境选 **Production**（不要 Preview）
4. 把 zip 拖进去 → **Save and deploy**
5. 等 20–30 秒

地址不变：`https://deep-portal.pages.dev`

## 什么情况要重发

| 你做了什么 | 要不要重发 |
|---|---|
| 往库里加了新文件 | 要（先发布该课程，再导出） |
| 改了已有文件的内容 | 要（重新发布该课程） |
| 只是改了待办 / 名单 | 不要 |
| 只是看了下页面 | 不要 |

## 为什么不能一键上传

桌面端是**本地应用**，它跑在浏览器里，只做两件事：读写你的磁盘目录、读写浏览器自己的数据库。

上传到 Cloudflare 需要你的账号凭据。把它放进网页里，等于把钥匙贴在门上——任何人打开页面都能拿到。所以这一步必须你手动做。

**这不是偷懒，是安全边界。**

## 常见问题

**Q：页面 404 / 白屏**
zip 里多套了一层 `portal` 目录。重新压：进到 `portal` 文件夹里，全选内容再压缩。

**Q：某个文件没出现在学生端**
超过 25MB 的不会打包。看 `portal\large-files.md`，把它传别处再手工加链接。

**Q：同学说链接打不开**
先自己用手机流量试（不要用 WiFi）。`pages.dev` 在国内偶尔不稳；备选 GitHub Pages。

**Q：想改名网址**
Cloudflare 里可以绑自定义域名，但要自己的域名 + 备案，不是必须。

**Q：发布记录越堆越多**
资料页「已发布」只显示未下架的，已下架的折叠在下面，可逐条删除。

## 四层结构（记住这个就不会乱）

```
I:\DataSystem\materials\   ← 你的原件
I:\DataSystem\publish\     ← 发布快照（决定哪些给同学看）
I:\DataSystem\portal\      ← 学生端成品
Cloudflare                 ← 同学看到的那一份复制品
```

改原件不会自动同步到最后两层，必须走一遍导出 + 上传。
