# 29 双端拆分方案（手机 / 桌面）

> 2026-11-24 21:20。目标：手机端只做待办 + 点名，桌面端只做资料。
> **本文只是方案，未动代码。**

## 1. 先给结论

**不要真开两个 Git 分支。**

分支的问题不在于创建，而在于之后：两边共用的部分（主题变量、顶栏、组件、CI 脚本）会立刻分叉，改一处要手工同步两次，一个月后基本无法合并。

推荐做法：**一套代码 + 构建开关**。

```bash
npm run build:mobile    # 只含 待办 / 点名，APK 用它
npm run build:desk      # 只含 资料 / 门户，桌面浏览器用它
```

开关是一个环境变量 `VITE_PLATFORM=mobile|desk`，在 `App.tsx` 里决定挂哪些路由、在 `AppShellHeader` 里决定显示哪几个导航项。

好处：共用代码只有一份，主题、组件、样式改动自动同步；坏处：代码里多几处 `if`。

> 如果你坚持要两个物理分支，本文第 6 节给了操作步骤，但我把风险写在前面。

## 2. 手机端要删什么

| 位置 | 现状 | 改动 |
|---|---|---|
| 顶栏导航 | 看板 / 作业 / 资料 | 去掉「资料」 |
| 看板「资料」卡 | 显示已发布包数量 + 进资料库按钮 | **整卡删除**，不占位 |
| 路由 | `view === 'library'` | mobile 构建下不可达，代码保留但懒加载剔除 |
| 平板断点 | ≤720 手机布局，>720 退回桌面两栏 | 手机上**任何宽度都只显示单列**，进平板横屏也不出现资料 |
| 底部 tab | 看板 / 待办 / 点名 | 不变 |

关键点：**平板比例下也不能露出资料**。现在 `>720px` 会切到桌面两栏布局，看板右侧就冒出资料卡。需要在 mobile 构建里把「宽屏回退」这条路直接掐掉——媒体查询换成由 `html[data-platform='mobile']` 控制。

## 3. 桌面端要留什么

| 位置 | 现状 | 改动 |
|---|---|---|
| 顶栏导航 | 看板 / 作业 / 资料 | 只留「资料」（可选加「关于」） |
| 看板 | 待办 + 作业 + 资料 | 整页移除；或保留成纯统计页（只读） |
| 待办 / 点名 | 完整功能 | 桌面端隐藏 |
| 资料库 / 门户发布 | 完整功能 | 保留，是唯一主线 |

桌面端不再挂 `MobileTabs`，也不再需要 `data-platform` 的手机样式。

## 4. 打包与标识

| | 手机 | 桌面 |
|---|---|---|
| appId | `com.shenfall.deeptime` | 不需要（浏览器） |
| 产物 | APK | `dist-desk/` 静态站点，拖 Cloudflare |
| CI | 现有 `android.yml` 改跑 `build:mobile` | 新增 `pages.yml` 或手动上传 |

如果以后桌面端也要独立安装包（Electron/Tauri），那是另一个决定，现在不做。

## 5. 实施顺序（估算 0.5 天）

1. 加 `VITE_PLATFORM` 开关与两个 build 脚本（30 分钟）
2. `AppShellHeader` / `App.tsx` 按开关挂路由（20 分钟）
3. 手机端：删资料卡、掐掉宽屏回退（30 分钟）
4. 桌面端：隐藏待办/作业（20 分钟）
5. CI 拆两个 job，各出一份产物（30 分钟）
6. 两端各跑一遍真机 / 宽屏验收（30 分钟）

## 6. 如果坚持两个分支

```bash
git checkout -b mobile    # 从 main 拉
git checkout -b desktop
```

风险清单：

- **共用文件**：`tokens.css`、`base.css`、`shell.css`、`theme.ts`、`components/*`。每次调色、改顶栏都要改两次
- **合并冲突**：一周后基本不可能干净合并，只能 cherry-pick
- **CI**：两分支各自维护 workflow，容易一份跑通一份变红
- **文档**：`13-status.md` 写哪一支？

**折中**：分支只用于「试点」，合并回 main 用开关区分，而不是长期并行。
