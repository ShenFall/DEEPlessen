# 07 技术方案

> 这一版只是选型判断，等界面定稿再细化。任何一条都可以推翻，但推翻要写进 ADR。

## 架构总览

```
┌─────────────────────────────────────────────┐
│ 学委端 SPA（本地优先）                        │
│  React + Vite + TS + Dexie(IndexedDB)        │
│  · 花名册、对账状态、任务 全部先写本地         │
│  · 有网时才同步到云端（可选）                  │
└──────────────┬──────────────────────────────┘
               │ 只在「发布资料 / 同步名单」时出网
┌──────────────▼──────────────────────────────┐
│ 边缘函数（Cloudflare Workers / Vercel Fn）    │
│  · 签发文件直链（7 天）                       │
│  · 口令校验                                   │
│  · 通知解析（调 LLM，可关）                    │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│ 对象存储（R2 / OSS）+ 只读清单表（D1/PG）      │
└─────────────────────────────────────────────┘
```

## 为什么本地优先

名单里有 40 个真实姓名和学号，属于别人的个人信息。**存不存云不是技术问题，是伦理问题。** 所以：

- 花名册、欠交记录、提交时间 → 只在本机 IndexedDB，默认不上传
- 需要换设备时，导出加密 JSON，手动搬运
- 只有「资料文件」和「资料清单」必须上云，因为它们的目标读者是全班

这回答了「不存很难」这个疑问：**要存，但存的是文件，不是人名。** 文件不进云端，学生就永远找不到，这是硬需求。

## 文件到底怎么存

| 环节 | 方案 | 理由 |
|---|---|---|
| 收录 | 微信/本地文件 → **复制进本地库**（`<库根>/materials/<课程>/`） | 原文件不动；库是唯一的「可发布」集合 |
| 发布 | 本地库 → 显式勾选 → 直传对象存储（预签名 URL） | 没有自动同步；一次只发一个文件 |
| 存储 | **本地盘是真相**，Cloudflare R2 只存已发布副本 | 断网/欠费不影响本地；出网流量免费 |
| 下载 | 边缘函数签发 7 天签名直链 | 防盗链，且可在过期后统一失效 |
| 微信内打开 | 直链 + `Content-Disposition: attachment` | 微信会拦部分类型，需实测 mp4/exe |
| 兜底 | 「用浏览器打开」提示 + 二维码 | 微信内置浏览器的下载限制绕不过去 |

**微信文件的收集问题**（他说的「微信文件很难找」）：PC 端微信的文件落在
`WeChat Files\wxid_xxx\FileStorage\File\2026-11\`，按月份分目录。P1 提供「拖入整个文件夹」批量上传 + 按修改时间排序；P2 如果做桌面壳（Tauri），可以监听这个目录自动入库。

## 安全边界（ADR-0008）

这台电脑上不只有课程资料，还有私人文件。所以「能读文件」这个能力必须被关进笼子：

| 边界 | 规则 |
|---|---|
| 目录 | 应用只认识一个**库根**，初始化时由你亲手选定；不得设在用户主目录或桌面 |
| 微信目录 | **不是库**，只是「可拖入的来源」。不索引、不扫描、不缓存 |
| 上传 | 没有任何后台自动同步。文件离开本机只有一条路：你点了「发布」 |
| 网络 | 桌面端**不监听公网端口**，不内建 HTTP 服务；分发只走对象存储签名 URL |
| 路径 | 所有路径先规范化再校验是否在库根内，拒绝 `..` 与跳出库根的符号链接 |
| 文件名 | 发布后对外只用随机 slug，原始文件名不进 URL |
| 权限 | 应用不申请管理员权限 |

**为什么不自己搭一台文件服务器**：一台对公网开放的机器，攻击面是整个操作系统；一个对象存储桶，攻击面只是一个 URL。真正会出事的情况不是「云被黑」，而是「自己把某个静态目录配错，把 `D:\` 挂上去了」。

## 学生端

- 纯静态 + 一次只读 API，`noindex, nofollow`
- 不做 SSR（没必要），首屏 3KB HTML + 图片懒加载
- 移动优先，最大宽 560px，`font-size: 15px`
- 备案问题：如果要用国内域名，需要 ICP；**先用 `*.pages.dev` 或 `*.vercel.app` 免备案跑起来**，稳定后再迁

## 通知解析

- 调一个便宜的小模型（结构化输出 JSON schema），超时 3s 降级为「保留原文 + 手动拆」
- **解析在边缘函数里做，不要在浏览器里放 API Key**
- 原话本地保留，只把文本发给模型，不发花名册
- 允许完全关闭（有人就是不想让第三方看见老师的通知）

## 现成引擎（2026-11 核对）

原则：**能装库就别自己写**。这个项目真正需要自己写的只有「对账交互」，其余都是胶水。

### Excel 解析：选 SheetJS，但**不要 `npm i xlsx`**

这是唯一一个必须小心的地方：

| 事实 | 说明 |
|---|---|
| npm 上的 `xlsx` 停在 **0.18.5** | 维护者早就不往 npm 发版了，`npm update` 永远升不上去 |
| 0.18.5 带两个 HIGH 漏洞 | `CVE-2023-30533` 原型污染（≤0.19.2）、`CVE-2024-22363` ReDoS（≤0.20.1） |
| 修复版只在官方 CDN | 装法：`npm i https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`，装完用 `npm ls xlsx` 确认不是 0.18.5 |
| 我们的风险边界 | 只解析**自己学校的教务系统导出文件**，不接受任意用户上传。但没理由带着已知 CVE 上线 |

正确写法：

```json
"dependencies": {
  "xlsx": "https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz"
}
```

**备选方案（如果确认学校只导出 .xlsx）**：

| 库 | 体积 | 取舍 |
|---|---|---|
| `read-excel-file` | ~40KB | 最轻，只读，schema 校验好用；**不支持 .xls** |
| `exceljs` | ~400KB | 强在写报表和样式，读脏文件不如 SheetJS 宽容 |
| SheetJS CE | ~900KB | 唯一同时支持 `.xls` + 脏文件容错 + 多 sheet 元信息。**动态 import，不占首屏** |

结论：**先用 SheetJS**，因为教务系统导出的 `.xls` 是真实存在的。以后确认用不上 `.xls` 再换 `read-excel-file`，能省 850KB。

### 其余依赖

| 需求 | 选择 | 理由 |
|---|---|---|
| 拼音索引 | `pinyin-pro` | 首字母、多音字、姓氏读音都有词库；40 人 <10ms |
| 模糊匹配 | 自写归一化 + `fastest-levenshtein` | 姓名匹配规则必须可解释，不能交给通用模糊搜索 |
| 本地库 | `dexie` | IndexedDB 事实标准，迁移机制够用 |
| PWA | `vite-plugin-pwa`（Workbox） | 生成 SW，离线壳开箱即用 |
| 离线状态 | `navigator.onLine` + 自定义心跳 | 只看 onLine 会误判（连上 WiFi 但没网） |
| 二维码 | `qrcode` | 生成取件码图片，不用在线 API（要联网） |
| 状态 | `zustand` | 比 Redux 轻 |
| 动效 | CSS transition 为主，`motion` 只用于 L3 | L3 可整层卸载，动画库不进主包 |
| 图标 | 内联 SVG | 全站 12 个图标，引库不值 |
| 对象存储签名 | R2 + `aws4fetch` | 预签名约 3KB，不用整个 AWS SDK |
| **不引** | UI 组件库（Ant / MUI / shadcn） | 默认圆角阴影会绑架视觉，深空皮肤要重写 80% 样式 |

### 体积预算

| 项 | 预算 |
|---|---|
| 首屏（HTML+CSS+JS，gzip） | ≤ 300KB |
| Excel 解析器 | 900KB，**动态 import**，只在打开导入页时下载，且被 SW 缓存 |
| PWA 安装后 | 全部离线可用，二次打开 0 请求 |

手机上加载 900KB 在教室里就是 20 秒白屏。所以解析器必须是 `import()` 而不是顶部 import——这条写进 M1 的验收。

## 数据体积估算

| 项 | 量级 |
|---|---|
| 一个班 40 人 × 6 门课 × 一学期 20 次作业 | 约 500 条提交记录，< 1MB |
| 资料（PPT/PDF） | 每学期 1–3GB |
| R2 存储成本 | 10GB 内基本免费；出网免费 |
| 函数调用 | 每月几千次，免费额度内 |

结论：**这个项目的边际成本接近 0**，不需要商业化，也就不要加任何多余的东西。

## 风险

| 风险 | 应对 |
|---|---|
| 微信拦截下载 | 实测 + 浏览器打开兜底 + 二维码 |
| 老师的资料有版权 | 默认 `noindex`、链接随机、学期末自动下线；不提供「全站搜索」给外网 |
| 名单泄露 | 本地优先；导出文件加密；分享页永不出现完整名单 |
| **真实名单进了 GitHub** | 仓库可能是公开的。`fixtures/` 只放脱敏样本；真实 `.xlsx` 与导出 JSON 写进 `.gitignore`，永不入库 |
| 单点故障（你电脑坏了） | 每周自动导出一次加密 JSON 到本地下载目录 |
| 项目烂尾 | P0 只做 4 个界面，2 周内能用起来，否则永远在「设计」 |
