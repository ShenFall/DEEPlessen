# 05 核心流程

## A. 建档：导入花名册（一学期一次）

```
新建班级 → 选学期 → 导入文件 → 列映射 → 预览三态 → 确认 → 生成 29 个 student
                                                    ↓
                                        标记离班人员（可逆，不删）
```

- 触发：首次进入，或 `/students/import`
- 失败处理：
  - 编码错 → 提示切换 GBK/UTF-8，给一份原始前 5 行的十六进制预览
  - 表头识别不到 → 手动点选列，记住映射
  - 重名 → 阻断，要求补学号
- **离班处理**：名单里有人已经不在班里（真实案例：`宋梓锐`，实际叫 `宋梓睿`，已离班）→ 标 `inactive`，**不做物理删除**，因为他名下还挂着历史作业与欠交记录。标记可逆，转回来能恢复
- 完成后：立刻生成一个 4 位班级码，用于后续分享链接的归属

## B. 收作业对账（核心，每周 3–6 次）

### 先纠正一个模型错误

v0.2 把对账设计成「批量导入已交名单 → 做差集」。这在真实节奏下是错的：

> 更多是零星几个人陆陆续续交作业。我收到第 27 份时，想知道还剩谁。

学委面对的不是「一次事件」，而是**一条流**。批量导入假设你手里已经有一份完整名单；流式现实里，名单是随时间一格一格长出来的。

所以主模型改成 **REPL**：默认全员未交，每来一个人就敲一次。40 次输入之后，剩下的亮格子就是答案。

- 批量导入降级为「补录工具」，只用于两种情况：白天收纸质、事后追认历史
- 主路径不需要「先有名单」才能开始，第 1 个人交的时候就能用

### 三种真实到达方式

| 到达方式 | 学委手上有什么 | 操作 | 耗时 |
|---|---|---|---|
| 微信文件 | `陈知远-作业4.pdf` | 拖进页面 / `⌘V` 粘贴 | 1 次拖拽，0 次点击 |
| 群里接龙 | 一段「1.张三 2.李四」 | 整段粘贴，自动拆 N 条 | 1 次粘贴标一批 |
| 口头 / 纸质 | 只有一个名字 | 命令行敲 `cz` ⏎ | 3 次按键 |

三条通道共用一个入口：**顶部那条命令行**。拖文件、粘文本、敲名字都落在这一条线上，输出统一是「标记某人已交 + 记一条证据」。

### 流程

```
作业卡 →「收作业」
  ↓
第 1 个人来了 → 拖文件 / 敲名字 → 标记 → 证据流 +1
  ↓（循环 27 次，每次 1–3 秒）
  ↓
第 27 份抬头看一眼：QUEUE 13，矩阵里 13 个亮格 → 答案就在那儿
  ↓
剩 1 人 → 界面换挡成大卡 → 记住这个人 → 你自己去微信说
  ↓
最后一人交了 → [OK] 40/40
```

### 关键交互规则

| 规则 | 说明 |
|---|---|
| 零点击也能用 | 拖文件自动从文件名取姓名；`⌘V` 自动尝试匹配剪贴板内容 |
| 默认全员未交 | 不预设「大家都交了」，没人交才是常态 |
| 键入即匹配 | `cz` / `2403` / `知远` / `眠羊` 都能命中，命中即回车 |
| 匹配不上就问 | 不猜。弹「这是谁？」候选，选中即把该写法记进别名表 |
| 已交只降权 | 见 ADR-0002。27 暗 13 亮，剩下的亮格子就是答案 |
| 时间戳自动打 | 每条标记带 `submittedAt`，期末算超时用 |
| 批量是补录 | 入口藏在「⋯」里，不占主位 |

### 为什么「名字不消失」在这里是决定性的

ADR-0002 当初的理由是「坐标不漂移」。流式场景给了第二个、更强的理由：

**如果勾掉的格子会消失，第 27 次标记之后，屏幕上剩下的 13 格就同时包含「还没交的人」和「你还没点到的人」——你分不清哪个是哪个。**

只有已交的人留在原地并变暗，才能形成「27 暗 + 13 亮」的对比，而这个对比本身就是答案。删掉已交的格子，等于销毁刚刚获得的信息。

### 失败处理

| 情况 | 处理 |
|---|---|
| 文件名叫 `作业4.pdf` | 不猜，命令行转「这是谁？」候选 |
| 一个人交了两份 | 不报错，更新 `updatedAt`，证据流标「重复提交」 |
| 敲错人 | `Z` 撤销，证据流那条同步撤回 |
| 27 人里有转专业的 | 花名册标 `inactive`，不进 QUEUE |
| 断网 | 本地照常标，联网后补同步 |

## C. 通知拆解

```
/notices → 粘贴框（Cmd+V 直接落进去）
  ↓
拆成 1–N 张任务卡，每张带：
  · 课程（自动上色）
  · 绝对时间（原文是「下周三」→ 换算成 11-25 23:59，并标注换算依据）
  · 置信度（确定 / 待确认 / 需你补时间）
  · 原文锚点（点一下高亮回原句）
  ↓
可编辑：拖一下改时间，改完记住这位老师的措辞
  ↓
落到时间轴 + 相关作业卡自动关联
```

失败处理：一句通知拆出 0 条 → 不硬拆，保留原文并提示「这条可能不是任务，要不要归档？」。拆出 5 条以上 → 折叠成「这条里有 6 件事，展开看」。

## D. 发布资料到学生端

```
/materials → 拖入文件（可批量）
  ↓
自动清洗文件名：计网复习提纲v3(1)最终版.pdf → 计网 · 期末复习提纲 v3
  ↓
自动打标：课程（从文件名猜）/ 类型（从后缀和关键词猜）/ 章节（可空）
  ↓
发布设置：公开 or 口令 | 有效期（默认学期末+7 天）
  ↓
生成：短链 / 二维码 / 一段可直接发群的文案
  ↓
学生侧：/c/<course> 或 /p/<slug>
```

**发群文案模板**（一键复制）：

```
【计网】期末复习提纲 v3 已上传
→ deep.shenfall.dev/c/jw
口令：无
找不到就在群里说一声
```

## E. 换班级 / 换学期

```
新班级 → 导入新花名册（走 A）→ 复制上学期课程结构 → 完成
旧班级自动 archived，历史数据只读保留
```

不做的：不做数据迁移工具。因为数据结构从一开始就按 `cohort + semester` 分好了，不需要迁移。
