# 03 信息架构

## 两个前台

```
deep/                          学委端（需口令，深空终端）
├── /today                     今日：谁欠我东西 + 今天要做什么
├── /assignments               作业：卡片列表，每张卡自带对账进度
│   └── /assignments/:id       对账台（队列 + 矩阵）
├── /materials                 资料：文件库 + 发布状态
│   └── /materials/:id         发布设置（范围、口令、有效期）
├── /notices                   通知：收件箱 + 拆解
├── /schedule                  日程：我的 / 班级 两层
├── /students                  花名册：班级管理、导入、别名
│   └── /students/import       导入向导
└── /settings                  设置：课程、学期、导出、清空

public/                        学生端（无需登录，纸白取件柜）
├── /c/:courseSlug             课程资料页（主入口，发到群里的就是它）
├── /p/:materialSlug           单份资料落地页（扫码进来）
└── /pickup/:code              4 位取件码 → 跳转到对应资料
```

## 学委端布局

- **左栏 56px**：只放图标（今日 / 作业 / 资料 / 通知 / 日程 / 花名册）。hover 展开成 200px 显示文字，离开收回。默认窄，是为了把宽度留给名单网格。
- **顶栏 44px**：左边当前学期与班级下拉，中间 `⌘K` 搜索，右边头像（就是那个头像，带轨道环）。
- **主区**：单列为主。只有「对账台」用两栏（队列 180px + 矩阵 1fr）。
- **右滑抽屉**：全局的「待办队列」，`⌘J` 呼出，任何页面都能看到还剩几件事。

## 移动端布局（<720px，主场景）

- **底部 4 tab**：今日 / 作业 / 资料 / 更多。不用 56px 左栏——手机上那是一条浪费的竖边
- **顶栏 44px**：返回 + 标题 + 一个关键数字
- **对账台全屏沉浸**：无 tab，只有左上返回。收作业时任何多余元素都是干扰
- **上传**：调系统文件选择器 / 相册，不做"监听文件夹"（手机上没有这个概念）
- 详见 [11-mobile.md](11-mobile.md)

断点：`<720` 手机 / `720–1100` 平板两栏 / `>1100` 桌面。

## 学生端布局

单列，最大宽度 560px，无导航、无页脚、无登录入口。只有一个搜索框 + 分类筛选 + 文件列表 + 一行「找不到？在群里 @ShenFall」。

**刻意不做的事**：不做「我的下载记录」、不做「学号验证」、不做「评论」。任何需要学生输入身份的东西都会流失一半人。

## 访问控制

| 对象 | 控制方式 |
|---|---|
| 学委端 | 单口令（本地存 hash），无注册、无找回。忘了就清 localStorage 重设 |
| 学生端 | 默认公开只读；可选 4 位口令（写在群公告里）；链接 `noindex`，slug 随机 8 位 |
| 文件 | 对象存储签名直链，有效期 7 天，页面每次打开重新签发 |

不做「仅本班可见」的学号白名单——同学不会为了看资料输学号，而学委也没法验证。

## 导航优先级

从上到下按「打开频率 × 紧迫度」排，不按模块重要性排：

1. 今日（每天开 10 次以上）
2. 作业（每周开 6 次，但每次很急）
3. 资料（每周开 3 次）
4. 日程（每天扫一眼）
5. 通知（收到就处理，处理完就不看）
6. 花名册（一学期开 2 次）
